## 🧠 Backend Overview

The SmartTrafficAI backend is implemented using **FastAPI**.

It provides a clean API layer between the frontend dashboard and results generated by the traffic simulation and controller experiments.

```text
Traffic / Emergency Experiments
             ↓
       Result Processing
             ↓
          FastAPI
        ↙         ↘
 Traffic API    Emergency API
        ↘         ↙
          REST API
             ↓
       React Dashboard
```

---

## 🏗️ Backend Architecture

```text
                     FastAPI Application
                            │
                 ┌──────────┴──────────┐
                 │                     │
          Traffic Router        Emergency Router
                 │                     │
                 └──────────┬──────────┘
                            │
                       Service Layer
                            │
                  Experiment Result Data
                            │
                       JSON Response
                            │
                     React Frontend
```

The backend does not perform municipal traffic control directly. It exposes the outputs of the SmartTrafficAI prototype and simulation pipeline to the monitoring interface.

## 🔌 API Endpoints

### System Health

```http
GET /api/health
```

Example response:

```json
{
  "status": "online",
  "system": "SmartTrafficAI",
  "simulation_engine": "SUMO",
  "controller": "TraCI",
  "api": "FastAPI"
}
```

---

### Traffic Comparison

```http
GET /api/traffic/comparison
```

Provides fixed-vs-adaptive SUMO experiment results including:

- Average queue length
- Maximum queue length
- Queue standard deviation
- Average travel time
- Average waiting time
- Average time loss
- Completed vehicle count

Example measured results:

| Metric | Fixed | Adaptive |
|---|---:|---:|
| Average Queue | 5.36 | **1.62** |
| Maximum Queue | 14 | **5** |
| Average Waiting | 12.63 sec | **4.27 sec** |
| Average Travel Time | 34.04 sec | **24.57 sec** |
| Vehicles Completed | 401 | 401 |

---

### Emergency Comparison

```http
GET /api/emergency/comparison
```

Provides results from the emergency-priority experiments.

The implemented multi-junction green corridor evaluates:

```text
AMB_001 → J1 → J2 → J3 → Hospital
```

Key experiment results:

| Metric | Normal Signals | Green Corridor |
|---|---:|---:|
| Travel Time | 99 sec | **69 sec** |
| Waiting Time | 33 sec | **0 sec** |
| Time Loss | 45.02 sec | **14.49 sec** |

---

### Emergency Status

```http
GET /api/emergency/status
```

Provides emergency-priority status information for the frontend monitoring layer.

## 🚀 Run Locally

From the SmartTrafficAI project root:

```bash

uvicorn app.main:app --reload --port 8000
```

The API will be available locally at:


## 🔄 Frontend Integration

The React application communicates with the production backend using Axios.

```javascript
const API = axios.create({
  baseURL: "https://backend-alpha-jet-55.vercel.app",
});
```

This separates the **presentation layer** from the **backend data/API layer**.

---

## 🧪 Experiment Integrity

The API exposes results produced by controlled **SUMO simulation experiments**.

The values returned by these endpoints represent prototype evaluation data and are not measurements from a deployed municipal traffic-control system.

This separation is important for responsible interpretation of the SmartTrafficAI results.

---

## ⚠️ Prototype Scope

SmartTrafficAI is currently an engineering prototype.

Future production deployment would require:

- Real-time validated traffic sensors
- Secure emergency-vehicle authentication
- Persistent production data infrastructure
- Traffic-controller fail-safe mechanisms
- Authentication and authorization for operational APIs
- Traffic-authority approval
- Large-scale field validation
